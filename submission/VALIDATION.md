# 第三版官方容器验证

验证日期：2026-10-04（Asia/Shanghai）。本轮主要减少全局布线入口的运行时间与检查内存，并扩大大设计的既有 HBT 重定位范围。默认共享仍为 192 条网、最多新增 384 颗 HBT，重定位保持两轮，移动上限从 4,096 提高至 65,536。所有用例使用相同源码和默认配置。

## 官方结果与覆盖范围

最终原生实现已完成全部 8 个公开用例的 GRT、guide 检查和官方 canonical 合法性验证；errors、warnings、超额 HBT 均为 0。全部实际走 `grt_pass_reset=native`。其中 `bp_fe` 还重新执行了完整固定 DRT/DRC/STA，没有复用历史质量指标。

## 大设计与实现改动

bp_quad 的既有 HBT 重定位从 4,096 颗增至 11,042 颗，两轮共接受 12,915 次移动，规划器统计的 HPWL 节省从 129,042.04 μm 增至 350,479.65 μm，约为原来的 2.72 倍。这是几何代理量，不是固定 DRT 线长或时序收益。新增 HBT 仍为 384，最终 HBT 总数 28,219，免费额度 45,630。

本轮实现包括：

- 公开 GRT 直接从 OpenDB 导出完整规划清单，避免逐对象 Tcl/SWIG 调用；保留 Tcl 回退。最终二进制在 bp_fe 全网表及真实 OpenDB 边界样例中逐字段一致；此前相同导出实现还对 bp_quad 的 1,363,004 条网、4,158,170 个 pin 完整对照。
- 两次非空 die 路由间用原生 API 清空待路由队列和 guide，保留每网硬层约束及最终完整 guide 导入。空 die 仍用原流程，`GRT_PASS_RESET=legacy` 可供对照。
- guide 诊断只保留所需对象，完整保留目标网全部 pin 与严格连通判据；合并重复扫描。bp_quad 的完整诊断内容、顺序和退出码与旧版一致，微基准峰值 RSS 从约 7,423,896 KiB 降至 526,992 KiB，减少约 92.9%。这不是整个入口的内存峰值。
- die 分类按网流式解析，在同次运行中用 DEF SHA256、完整分类内容 SHA256 和结构验证复用分类；缺失、损坏或不匹配即重新全量分类。所有 guide 矩形仍检查。
- 新增细分阶段计时，`grt.prepare` 包含 `mls.*` 子项，不能将全部细分项直接相加。

共 51 项 Python 回归测试通过，另完成 1,000 次随机诊断差分、真实大小用例完整输出比较、原生导出边界对照；Python 语法、Shell 语法与 Git whitespace 检查通过。

## 参数筛选

提高共享容量、放宽聚类和增加重定位轮数的三个候选均在相同官方版本中做了完整 bp_fe DRT/STA，均未作为默认配置：

| 候选 | DRC | DRT 线长 (μm) | TNS (ns) | WNS (ns) |
|---|---:|---:|---:|---:|
| v2 基准 | 4,059 | 1,342,836.13 | -8,253.17 | -3.33894 |
| 扩大共享容量 | 4,197 | 1,342,885.56 | -8,303.00 | -3.47972 |
| 放宽聚类 | 4,104 | 1,342,787.95 | -8,324.97 | -3.45971 |
| 扩大共享并做四轮重定位 | 4,116 | 1,339,020.67 | -8,431.87 | -3.72465 |

三个候选均合法，但 DRC、TNS、WNS 都比 v2 差。最终保留原共享规模和两轮重定位，只提高移动上限，避免大用例在第一轮被截断；bp_fe 的规划结果不变。
