# v22：位置保护选层与规划执行加速

路由策略继承 v21：高扇出共享网最多使用两个接收端分组；新增 HBT 上限为 min(384, floor(0.30 × 规划网格容量) − 已有 HBT 数)，负值取零，最多选择 192 个共享网。已有 HBT 在原 6.4 μm 格点上优化；逐接收端几何路径保护、候选顺序及合法性判断保持不变。

底 die 使用 metal2–metal10，上 die 使用 metal11–metal20。普通高扇出选层要求 fanout ≥ 512、HPWL ≥ 400 μm，并排除时钟、HBT/MLS 和封装 pin；满足 v21 驱动位置保护条件的底 die 普通网使用 metal3–10，否则沿用 metal4–10。各层容量折减参数保持 metal2=0.75、metal3=0.65，其余为 0.50，GRT 迭代参数不变。规则只依赖当前输入，不依赖用例名、历史得分或评估后的关键 pin。

本版只改变独立 Python 规划 CLI 的执行方式。大型网表由无循环引用的 JSON/几何记录组成，CLI 暂停循环垃圾回收以避免反复扫描所有存活记录；引用计数继续回收废弃对象，成功或异常退出都会恢复原状态，库导入不改变 GC 策略。完整计划以紧凑 JSON 写出，保留所有字段、顺序和数值，使用 Python 的 C JSON 编码器。生成的 Tcl 和原生路由覆盖层与 v21 相同。

单进程双 die 路由、包内默认配置下 GRT-0228/GRT-0254 的一次新进程重试、guide 层归属与连通性检查、独立 ODB 重开及成功后发布机制保持不变。详细继承策略见包内 HISTORY_V21_ALGORITHM.md；本轮实际验证范围及计时见 VALIDATION.md。v21 在当前保存结果中为 25.81 分，本版没有新的官方分数。
