# v16：固定两组共享分支与有界回退

本方案将高扇出共享连接族的接收端分组上限设为 2，关闭自适应分组和整族树长度筛选，使用固定分组的几何候选。分支族内默认保留逐接收端路径筛选：借用上层后的曼哈顿路径不得超过原始直连路径的 1.05 倍再加 6.4 μm，含借线权重和接入代价的路径代理也不得超过原始直连；不满足条件的接收端留在源端本地连接。这些约束作用于几何代理，最终 WNS/TNS 由实际布线、寄生提取和 STA 决定。

新增 HBT 预算取 `max(0, min(384, floor(0.30 × 规划器网格容量) − 已有HBT数))`；最多选择 192 个共享网，HBT 使用输入的 6.4 μm 间距格点。默认 GRT 资源折减参数为 `metal2=0.75,metal3=0.65`，其余层为 `0.50`，对应 75%、65%、50% 的容量折减设置；各层覆盖统一折减设置。默认 GRT 参数包含 `-allow_congestion -congestion_iterations 1`。

提交入口只有在使用包内默认 MLS 配置且首次原生 GRT 报出 `GRT-0228` 或 `GRT-0254` 时，才保存失败日志并进行一次重试。重试启动新的 OpenROAD 进程，从原始 CTS 输入重新加载设计，使用包内保留的原 8 组参照、自适应及树长度筛选配置重新规划和路由。自定义配置、其他错误和重试失败均继续向上传播；原生完整性检查保持启用。

继承的3D流程按bottom `metal2–metal10`、upper `metal11–metal20` 分别路由，使用本次网分类、MLS计划及受限普通高扇出网提示选层；HBT边界连接在准备和最终guide处理阶段完成。默认 `GRT_PROCESS_MODE=single`、`GRT_INPUT_MODE=auto` 直接读取原CTS DEF/SDC，在同一进程完成准备与两个die pass；`isolated` 模式使用转换后的初始ODB，显式 `odb` 输入也保留支持。默认执行guide层归属与完整连通性检查，并独立重开新ODB验证成功后发布 `5_1_grt.odb` 及 `route.guide`；`SUBMISSION_EXPORT_DEF=1` 可从最终ODB导出补充DEF。原生准备信息默认自动使用，输入不兼容时采用原DEF解析路径。继承实现的详细说明及历史验证保存在包内 `HISTORY_V15_ALGORITHM.md`。

既有 HBT 重定位、需求网格及确定性排序继续执行；不把算例名或评估后的关键 pin 写入决策。逐接收端的几何代价是规划代理，不能证明实际 RC、WNS 或 TNS 无回退。选择依据为固定五例的完整 DRT（end_iter=2）、RCX 和 STA，其中 SW 在原始提交 ODB 及原 GRT guide 双字节身份核验后复用既有完整评测。

普通高扇出选层沿用输入驱动的条件：fanout 至少512、HPWL 至少400 μm、最多256条，排除时钟、HBT/MLS和package-pin网，保留pin接入及die硬窗口。默认底die主干metal4–10、上die主干metal11–17；候选共享分支借用上die金属层时仍遵守原几何保护。

加载设计时使用匹配输入master的公开LEF/Liberty，全部检查成功后才发布最终结果；失败继续返回错误。原生13份覆盖层不变。准备元数据复用、索引和检查调度的历史说明保存于 [HISTORY_V15_ALGORITHM.md](HISTORY_V15_ALGORITHM.md)，当前参数以本文和包内配置为准。
