# 第 15 轮：低层布线容量与时序/DRC 对照

本轮得到一个可供官方复测的 capacity75 候选：五例 DRC 总数从 39079 降到 34849（减少 10.82%），WNS 损失减小 0.38%，TNS 损失增加 0.28%。提交入口采用 M2/M3 削减 75%/65%，保留原 24.02 分提交 ZIP。该候选包含明确的时序取舍，尚不能确认提升官方总分或达到 27 分。

已知官方成绩是 **24.01565788837513（显示 24.02）**，来源为
`result/scoring_result-6/scores.json`。本轮没有新的官方评分，**27 分尚未验证**。

## 参数与依据

以实际获得 24.02 分的 v14 源码为基线，保留 384-HBT 预算、接收端路径保护、
4/8/16 分组与完整连接树保护。本轮完整质量候选只调整全局布线的层容量削减比例：

| 方案 | M2 削减 | M3 削减 | 其他层削减 |
|---|---:|---:|---:|
| 官方 v14 | 70% | 60% | 50% |
| capacity75 | 75% | 65% | 50% |
| capacity80（FE/BE 对照） | 80% | 70% | 50% |

比例越大，GRT 假定可用的资源越少，为详细布线预留的空间越多；物理 TRACKS
与工艺平台不变。依据为 [OpenROAD 容量调整说明](https://openroad.readthedocs.io/en/latest/main/src/grt/README.html#set-global-routing-layer-adjustment)
及 [CUGR 的详细可布线性研究](https://github.com/cuhk-eda/cu-gr)。本轮没有复现 CUGR，
文献收益也不作为本方案的得分证据。

## 完整实测

以下只列已完成并保留完整证据的测量。TNS/WNS 越接近零越好，DRC 越小越好。

| 用例 | 候选 | TNS / ns：官方 → 本地 | WNS / ns：官方 → 本地 | DRC：官方 → 本地 |
|---|---|---:|---:|---:|
| bp | capacity75 | -159108 → -160116 | -22.538 → -22.3637 | 13448 → 11032 |
| bp_be | capacity75 | -6624.01 → -6857.03 | -3.80213 → -4.22722 | 4701 → 4223 |
| bp_be | capacity80 | -6624.01 → -6750.83 | -3.80213 → -4.02286 | 4701 → 4145 |
| bp_fe | capacity75 | -6544.23 → -6564.87 | -3.24734 → -3.22119 | 1811 → 1479 |
| bp_fe | capacity80 | -6544.23 → -6569.59 | -3.24734 → -3.20018 | 1811 → 1264 |
| bp_multi | capacity75 | -83525.9 → -82989.5 | -16.651 → -16.2459 | 4887 → 3772 |
| swerv_wrapper | capacity75 | -1843.43 → -1849.42 | -1.55263 → -1.5531 | 14232 → 14343 |

FE 的官方提交 ODB 经本轮固定评测器重新运行，TNS、WNS、DRC、详细线长与 HBT
数量全部精确复现。capacity80 的 FE 违例减少 547 个，其中 M2 层净减少 484 个；
最差路径起点和终点相同。其 TNS 略有回退，因此不能只凭 DRC 或 WNS 判断整体收益。

BE 的 capacity75 把 DRC 从 4701 降到 4223，却使 WNS 从 -3.80213 ns 变为
-4.22722 ns。同一起点/终点路径中，包含 MUX 的报告级延迟约从 1.11 ns 增至
1.67 ns。这里的级延迟合并了前级连线与单元弧，不能单独解释为纯线延迟或单元延迟。

## 验证范围

- `baseline`：1 例合法性通过，1 例完成固定 DRT/RCX/STA。
- `capacity75`：8 例合法性通过，5 例完成固定 DRT/RCX/STA。
- `capacity80`：2 例合法性通过，2 例完成固定 DRT/RCX/STA。

固定引擎来自官方镜像 `gaocr/3dbench-contest:20260914`，使用镜像动态库在本机执行，
每个质量任务 8 线程，保持官方 `end_iter=2`、RCX、HBT 寄生参数和 STA。
平台逐文件与公开输入核对；评测器在执行前后校验摘要。该结果属于本地固定引擎测量，
不是新一轮服务器评分。工作目录在 RAM，已完成证据另存于持久目录。

五个已生成质量候选的 HBT 位置、分组、连接关系和保护网集合均与官方 v14 相同。
跨 Python 版本的计划 JSON 在诊断用浮点统计上存在最大约 2.5e-10 的差异，
不声称整个计划文件与服务器逐字节相同；实际物理计划相同。

222 项既有生产测试、4 项树长度/输入/缓存保护测试、7 项支持工具测试通过。
本地入口耗时来自共享宿主，不能与服务器 Runtime 直接相减；详细评测耗时不是计分的入口耗时。

FE 与 BP 均完成两轮 8 线程交替入口对照（原方案/候选，再候选/原方案）。
FE 平均 16.947 → 17.162 秒（+1.26%），BP 平均 109.310 → 110.432 秒（+1.03%）。
各轮提交 ODB 和 guide 都与对应质量评测输入逐字节相同。该小样本共享宿主观测
不证明运行时间改善，也不能换算服务器得分。原始记录在 `paired_runtime.json`。

官方原记录中 `ariane133`、`ariane136`、`bp_quad` 报 `Input DEF file not found`。
本地合法性通过不能证明该服务器输入问题已修复。完整归一化计分公式不可得，
因此不根据局部指标推算 27 分。
